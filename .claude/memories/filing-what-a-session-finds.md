# Filing what a session finds

File the issue when the session finds the defect. Do not describe it in a reply and ask whether to file it.

**Why:** A reply is not a record. The next session reads the repository and the issue tracker, and a defect that lives in a transcript is one nobody will meet again. Asking first also puts the finding at the end of a queue of its own: the answer arrives after the session that found it has moved on, and the reading that made the finding possible has to be done a second time to write it up.

**How to apply:** Most findings arrive while working on something else. Finish the work in hand first, then file, so the issue is written from what the reading established rather than from what the fix happened to touch. Check [what-does-not-get-filed](what-does-not-get-filed.md) first, and split by scope per [splitting-what-one-reading-found](splitting-what-one-reading-found.md).
